# 文档索引

新会话先读根目录的 `CLAUDE.md`，那是最短的入口。这里是全部文档。

| 文档 | 内容 | 什么时候读 |
|---|---|---|
| [信息雷达与探索队列方案.md](信息雷达与探索队列方案.md) | 产品方案 0.1 版，五个阶段的完整设计 | 想知道"最终要做成什么"、某个功能属于哪一阶段 |
| [架构.md](架构.md) | 抓取管线的数据流、每个模块的职责与边界 | 动 `scripts/` 或 `lib/` 之前 |
| [数据契约.md](数据契约.md) | `data/*.json` 的字段定义与不变量 | 加字段、加来源、写前台之前 |
| [来源清单.md](来源清单.md) | 9 个来源的抓法与已知坑（实时状态跑 `npm run check-sources`） | 加来源、排查某个来源没数据 |
| [决策记录/](决策记录/) | 为什么这么做（ADR），只增不改 | 想推翻某个约定之前 |

`research/` 下是调研笔记，不参与构建，也不保证与当前实现同步。

## 维护规矩

- **改了管线结构就同步改 `架构.md`**，改了事件字段就同步改 `数据契约.md`。
  文档与代码不一致时，以代码为准，然后立刻修文档。
- **做出会约束未来的决定，写一条 ADR**，不要只写在提交信息里。
  编号递增，已发布的 ADR 不改内容，要推翻就写新的一条并在旧的顶部加一行指向它。
- `CLAUDE.md` 的「已知问题」一节是活的：修掉一条就删一条，发现一条就加一条。
