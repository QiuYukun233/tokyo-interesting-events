# 信息获取管道设计

**日期：** 2026-08-28
**状态：** 提案，未实施

对应方案 §3（广泛信息雷达）与 §11 阶段 1。这份文档回答一个问题：
**候选从哪来，以及为什么是这些地方。**

本文里的每个数字都是当天实测的，不是估计。探测脚本的做法记在最后一节。

## 1. 缺口有多大

当前 `data/events.json` 共 **34 条**。按开始时间拆开：

| 状态 | 条数 |
|---|---|
| 已在进行（长展期） | 17 |
| 未来 7 天内开始 | 8 |
| 8–14 天 | 1 |
| 15–30 天 | 3 |
| 更远 | 5 |

方案 §7.1 要求每轮探索队列 12–20 项，且类型必须多样。**现在的库存大约够一个人一轮**，
而且 34 条里 16 条是美术馆/大学展览，`vibe` 只有三种（奇妙体验 16 / 艺术现场 12 / 好好聊天 6）。

方案 §10 的运营漏斗设定是每周 1,000 条原始候选。**当前约每周 60 条，差约 16 倍。**

缺的不只是量，还有类别。方案 §3.2 列的六个来源家族里，我们只覆盖了三个：

| 方案 §3.2 家族 | 当前来源数 |
|---|---|
| 大型展馆与公开展会 | 1（Big Sight） |
| 艺术、设计与特殊空间 | 4（都美术馆 + 藝大三馆） |
| 大学与研究机构 | 2（东大、早大） |
| **新运动与参与式消遣** | **0** |
| 店铺生命周期 | 2（涩谷/池袋经济新闻） |
| **小型文化与亚文化** | **0** |

## 2. 实测：哪些路走得通

在设计之前先测了七条常见路径。**其中三条直觉上最该成立的，实测是死的**，
所以这一节比结论本身重要。

| 路径 | 实测结果 | 判定 |
|---|---|---|
| `schema.org/Event` JSON-LD | 8 个东京场馆站，**0 个**发布 Event 类型（Big Sight 只有 BreadcrumbList，PARCO 只有 NewsArticle） | ❌ 死路 |
| iCal `.ics` 订阅 | 东大、科学未来馆、都美术馆全部 404 | ❌ 死路 |
| `<link rel=alternate>` RSS 自动发现 | 8 个站里 0 个声明 | ❌ 死路 |
| 東京都开放数据 CSV（Big Sight） | **154 场**，14 字段含来场对象/入场费/内容/URL | ✅ 立即可用 |
| 東京都开放数据 CSV（区级） | 19 张事件表，未来 180 天内合计仅 **35 条**，多数是历史归档 | ⚠️ 低产但近乎免费 |
| みんなの経済新聞 地域版网络 | 东京圈 **15 版可达**，robots 全部允许，URL 结构完全一致 | ✅ 高性价比 |
| Tokyo Art Beat 内嵌 JSON | 单页 **1000 条**，字段最全，还带人气/收藏/到访数 | ⛔ 利用规约禁止 |

**结论一：日本的活动信息没有可利用的机器可读标准。** 想靠一个通用 JSON-LD 或 iCal
适配器一次接完几十个场馆——这条路在东京不存在。任何声称"用标准协议批量接入"的方案
都要先跑上面这个探测再说。

**结论二：真正的杠杆不在"加新来源"，而在"已有来源严重欠采"。**

## 3. 最大的两处欠采

### 3.1 Big Sight：HTML 爬到 10 条，开放数据有 154 条

我们现在用 `tokyo-big-sight.mjs` 解析 HTML 列表页，拿到 10 条。
而東京都开放数据目录里有官方 CSV：

```
https://www.opendata.metro.tokyo.lg.jp/tokyobigsight/tokyobigsighteventinformation.csv
```

Shift_JIS 编码，154 行，表头：

```
展示会名, 会期(開始), 開始曜日, 会期(終了), 終了曜日, 利用施設, 開催時間,
最終日の終了時刻, 来場対象者, 入場料について, 内容, 連絡先, TEL, URL
```

`来場対象者` 一列的分布是关键：

| 来场对象 | 场次 |
|---|---|
| 商談 | 129 |
| 商談/一般 | 13 |
| 一般 | 12 |

**25 场对一般人开放**，而我们当前从 Big Sight 只发布了 3 条。而且这 25 场正是方案
§5.2 说的那类"商谈展但值得普通人去"的东西：Maker Faire Tokyo 2026、
ジャパンレプタイルズショー、第64回全日本模型ホビーショー、日本ダーツ祭り、
COMIC CITY SPARK 21、GOOD LIFE フェア。

附带好处：`isPubliclyAccessible()` 现在靠正则匹配 `audience` 里有没有「一般」，
是启发式的；换成开放数据的 `来場対象者` 就是**主办方自己填的权威字段**。

### 3.2 みんなの経済新聞：接了 2 个版，网络里有 15 个

我们有 `shibuya-keizai-shop-changes.mjs` 和 `ikebukuro-keizai-shop-changes.mjs`
两个适配器，逻辑相同。实测东京圈可达的地域版：

```
shibukei.com          ginza.keizai.biz      shinjuku.keizai.biz   akiba.keizai.biz
roppongi.keizai.biz   koenji.keizai.biz     shimokita.keizai.biz  kichijoji.keizai.biz
asakusa.keizai.biz    shinagawa.keizai.biz  machida.keizai.biz    hachioji.keizai.biz
tachikawa.keizai.biz  nerima.keizai.biz     ikebukuro.keizai.biz
```

全部 `robots.txt` 允许，首页各约 17–31 篇文章，URL 结构统一为 `/headline/NNNN/`。

**这 13 个新版是配置行，不是新代码**——只要把现有解析器抽成一个「みんなの経済新聞」
家族适配器，注册表里多 13 条即可。这也直接补上「小型文化与亚文化」和
「店铺生命周期」两个空缺家族：这个网络报道的正是独立书店、live house、
小剧场、澡堂、模型店这类东西。

## 4. 设计

### 4.1 接入方式要可插拔

现在 `SOURCES` 的每一项都假定 `parse(html, source)`——只支持 HTML。
Big Sight 的 CSV 和区级开放数据接不进来。

改成按 `accessMethod` 分派取数器：

```
run-ingestion.mjs
  └─ fetchSourcePages(source)
       ├─ accessMethod: 'html'  → 现在的行为
       ├─ accessMethod: 'csv'   → 取字节 → 猜编码(UTF-8/Shift_JIS) → 正规 CSV 解析 → 交给 source.map(row)
       ├─ accessMethod: 'json'  → 取 JSON → source.map(obj)
       └─ accessMethod: 'rss'   → 现有 rss.mjs
```

`accessMethod` 字段注册表里**已经有了**（0002 那轮加的），现在只是没人用它分派。

两个必须内建的细节，都是实测踩到的：

- **编码嗅探**：东京都的 CSV 是 Shift_JIS，直接按 UTF-8 读会全是乱码。
  策略是先按 UTF-8 解，数 U+FFFD 替换字符，超过阈值就换 Shift_JIS 重解。
- **正规 CSV 解析**：不能按行 `split(',')`。区级数据的字段里有带引号的逗号**和换行**——
  我第一次统计町田市时数出 3091 行，正规解析后实际只有 9 行。

### 4.2 来源家族：一个解析器，N 条注册

みんなの経済新聞 15 版是这个模式的样板。注册表结构改成：

```js
{
  family: 'minkei',                    // 共用解析逻辑
  parse: parseMinkeiArticle,
  members: [
    { name: 'シブヤ経済新聞', origin: 'https://www.shibukei.com', area: '涩谷' },
    { name: '銀座経済新聞',   origin: 'https://ginza.keizai.biz',  area: '银座' },
    ...
  ]
}
```

健康监测按 member 独立计数（`lib/source-health.mjs` 已经用 `name::url` 做 id，
天然支持），所以某一个版改版失效不会被其他 14 个版的正常数据掩盖。

### 4.3 发现机制：让新来源自己冒出来

東京都的 CKAN 目录（`catalog.data.metro.tokyo.lg.jp/api/3/action/package_search`）
共 **9,658 个数据集**，其中 81 个匹配「イベント」。它是标准 CKAN，可以定期轮询：

```
npm run discover-sources   # 每周一次
  → CKAN package_search 关键词扫描
  → 与 data/source-registry.json 比对，列出「目录里有但我们没接」的数据集
  → 写进候选来源清单，等人决定接不接
```

这条不是为了区级那 35 条，是为了**新数据集出现时我们能知道**。
Big Sight 那份 CSV 就是这么找到的。

### 4.4 要申请的来源

有三个高产源不能直接抓，但可以合法拿到：

| 来源 | 障碍 | 需要做的事 |
|---|---|---|
| connpass | API v1 返回 403，v2 需要 key | 免费注册申请 API key |
| Doorkeeper | API 本身 200 且无需鉴权，但 `api.doorkeeper.jp/robots.txt` 是 `Disallow: /` | 确认其 API 使用条款是否独立于 robots；有公开文档的 API 与爬虫是两种契约，但要问清楚再用 |
| Tokyo Art Beat | 利用規約 §9.1(l) 禁止未经许可的系统性下载 | 需要联系取得许可。他们本身有「展覧会情報の掲載」业务，是聚合方，谈合作并非无理 |

**在拿到明确许可之前，这三个都不接。** 尤其 TAB：它一页 1000 条、字段最全、
还带人气信号，诱惑最大，所以要写在这里提醒自己别抄近路。

### 4.5 类别缺口怎么补

「新运动与参与式消遣」和「小型文化与亚文化」两个家族目前是 0。
みんなの経済新聞 15 版能覆盖一部分（它报道 live house、独立书店、小剧场）。
剩下的需要**逐个场馆**接，没有捷径——这正是 §4.2 家族机制要省下的人力该花的地方。

## 5. 分阶段与预期产出

数字是按上面实测推的，**不是承诺**：区级开放数据的低产已经证明这类估计会偏乐观。

| 阶段 | 做什么 | 预期新增 | 成本 |
|---|---|---|---|
| **1** | CSV 取数器 + Big Sight 换开放数据 | Big Sight 3 → **25 条一般可入场** | 一个取数器 + 一个 map 函数 |
| **2** | みんなの経済新聞抽成家族，注册 13 个新版 | 现有 2 版产出 × 7.5，且补上两个空缺家族 | 重构一个适配器 + 13 行配置 |
| **3** | CKAN 发现脚本 + 区级标准数据集适配器 | 约 35 条，但发现能力是长期的 | 一个脚本 + 一个适配器 |
| **4** | 申请 connpass / Doorkeeper / TAB 许可 | 未知，可能很大 | 主要是等回复 |
| **5** | 按家族补新运动、亚文化场馆 | 逐个场馆 | 人力密集 |

阶段 1+2 不需要任何新的许可谈判，也不需要新的解析技术，**是纯粹的欠采修复**。

## 6. 需要你决定的事

1. **要不要去谈 TAB / Doorkeeper / connpass 的许可。** 这是发邮件的事，不是写代码的事。
2. **区级开放数据接不接。** 未来 180 天只有 35 条，但成本是一个适配器；
   接了以后每年会不会变多，取决于各区自己更不更新——目前看多数区已经停更了。
3. **阶段 5 的场馆名单谁来定。** 「新运动」「亚文化」这两类没有现成目录，
   需要有人按兴趣列场馆，机器帮不上忙。

## 7. 探测怎么做的

上面每个数字的来源：

- **JSON-LD / RSS 自动发现**：对 8 个场馆的列表页与详情页取 HTML，
  正则抓 `application/ld+json` 块解析 `@type`，抓 `<link type="application/rss+xml">`。
- **开放数据**：CKAN `package_search?q=イベント&rows=100`，
  逐个下载 CSV 资源，按表头是否含 `イベント名`/`展示会名` 过滤掉「公共施設一覧」
  （**这一步我第一次漏了，把 23 张设施表当成事件表，多算了约 5000 行**），
  再按 `開始日` 列统计未来 180 天内的条数。
- **みんなの経済新聞**：对 20 个候选域名取首页与 robots.txt，
  数 `/headline/\d+/` 形态的链接。
- **利用规约**：直接读 TAB 的 `/termsOfUse` §9 禁止事項。

复现这些探测不需要仓库里的代码，都是独立脚本。**如果三个月后要重新评估某条路径，
重跑探测比读这份文档可靠**——网站会变。
