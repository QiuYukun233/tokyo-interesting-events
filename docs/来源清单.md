## 开闭店与小型文化（`npm run collect-shop-changes`）

みんなの経済新聞ネットワーク，**15 个东京圈地域版共用一个适配器**
（`minkei.mjs`），robots 全部允许：

```
シブヤ / 池袋 / 銀座 / 新宿 / アキバ / 六本木 / 高円寺 / 下北沢
吉祥寺 / 浅草 / 品川 / 町田 / 八王子 / 立川 / 練馬
```

两段式：抓一次首页取开闭店线索，再只抓命中的文章页。超过 45 天的线索丢弃。
这个网络报道独立书店、live house、小剧场、澡堂、模型店，同时补上方案 §3.2 的
「店铺生命周期」与「小型文化与亚文化」两个家族。

判定在 `lib/shop-publication-policy.mjs`；涩谷版沿用它自己更早的策略，
其余 14 版共用一条规则，直到有证据要分开。

## 已知的坑

**早稲田大学的 robots.txt 取不到（已解决，但留个说明）。**
`https://www.waseda.jp/robots.txt` 返回的是 Cloudflare 的 403 挑战页，换任何
User-Agent 都一样（含空 UA 与浏览器 UA），而活动列表页 `/top/event/list` 对我们的
UA 正常返回 200。所以这个站**没有可取回的 robots.txt**，不是它禁止了我们。

此前管线按"非 2xx 即拒抓"处理，把这个来源整个丢掉了。现在按 RFC 9309 §2.3.1 办：
4xx 表示 robots.txt 不可用、可以访问；429 与 5xx 表示答案未知、不抓。
但**非 404 的 4xx 会在注册表里记 `robots_unavailable` 警告**——放行是明面上的，
不是悄悄的。

如果哪天早稲田的 robots.txt 变得可读且写了 Disallow，管线会自动改回拒抓，
不需要改代码。

**Big Sight 的公开性判定仍然只看一个字段。** `isPubliclyAccessible()` 检查
`audience` 是否含「一般」。换成开放数据后这个字段变成了主办方的权威声明，
比原来的正则猜测可靠得多，但方案 §5.2 的五条保留条件（能否合法报名、
是否要求虚构身份、现场有无实体展示等）仍然一条都没实现。

**`audience` 字段有两套语义。** Big Sight 用它表示「谁可以来」，
而 `utokyo-events.mjs` 用它装「オンライン」「本郷地区」这类地点/形式。
目前 `isPubliclyAccessible()` 只作用于 Big Sight 所以没有实际冲突，
但这是个契约隐患。

**藝大三个馆共用 `source` 字段。** 三条来源同名，前台无法区分，只能靠 `place`。
注册表里靠 `name::url` 组成的 id 区分，所以健康监测不会把它们混在一起。

## 加一个来源要做的事

1. 先看 `robots.txt` 与使用条款。
2. 在 `scripts/sources/` 建 `<来源>.mjs`，导出 `parse<来源>(html, source)` 和 URL 常量；
   用 `createEventCandidate()` 造记录。
3. 同目录建 `<来源>.test.mjs`，**用内联 HTML 夹具**，不要打网络。
4. 注册进 `scripts/sources/index.mjs`，**填对 `accessMethod`**
   （`html` 用 `parse(html, source)`；`csv`/`json` 用 `map(record, source, index)`，
   取数与编码嗅探由管线负责），并填全方案 §3.3 的字段：`sourceFamily`、
   `trustTier`、`accessMethod`、`crawlFrequency`、`expectedUpdateWindowDays`、
   `robotsAndTermsCheckedAt`、`parserVersion`、`ownerOrContact`。
   **改解析器时同步改 `parserVersion`**——它是重写之后用来定位"该复查哪些来源"的东西。
5. 跑一次 `npm run update-events`，再跑 `npm run check-sources` 确认没有告警，
   把原始条数补进上面的表。
6. **不要新建 `index-v2.mjs`。** 见 `决策记录/0001-收敛版本树.md`。
