# 0006 闸门降级为纯事实闸门；品味分家到云端 votes

2026-08-31。设计全文见 `docs/探索队列设计.md`。

## 问题

后台积压 800+ 条待判，其中大多数是「我不感兴趣但也不至于删掉」的中间地带——
尤其体验类（没看过的舞台剧根本没法逐条判好坏）。审核者被迫在
published/rejected 两个都不对的选项里选一个。这正是方案 §9 警告过的混淆：
`taste_no`（不感兴趣）和 `bad_source`/资格不合（事实不合格）是两种否定，
混在一起系统会学错，人也判不动。

## 决定

1. **闸门只判事实。** `decisions` 回答「能不能收录」：非公众、信息可疑、
   不是可去处、已消失。不回答「好不好」。
2. **品味是滑出来的，不是判出来的。** 探索队列（部署在 Vercel + Turso）
   每轮出 12–20 题，用户三态滑动，结果写云端 `votes` 表。
3. **votes 与 decisions 永不互写。** 「不想去」不产生 rejected；
   撤回一个判决也不影响任何 vote。
4. **记录之源分家：** pool.db 管候选+事实判决；Turso 管 votes。
   `push-cloud` 单向上行事实合格集合，无回流。
5. **「published」语义退役。** 前台不再展示「已发布集合」，
   历史 published 判决追认为事实合格证据，不预填想去清单。

## 后果

- 积压不再需要逐条人工判；人工只处理事实性存疑的少数。
- 0002 的方向不变：事实规则继续从判决里长；品味规则将来从 votes 里长。
- 0005 的廉价模型初判，判的对象随之变窄：只初判事实合格性，不初判品味。
- 抓取链路完全不动（0003/0004 仍然成立）。
