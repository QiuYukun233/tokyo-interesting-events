# 0001 · 用 git 管版本，不用文件名管版本

**日期：** 2026-08-28
**状态：** 生效

## 背景

2026-08-28 接手时，仓库里同一个模块存在最多 6 份平行副本：

- `scripts/update-events.mjs` 到 `update-events-v6.mjs`
- `scripts/sources/index.mjs` 到 `index-v5.mjs`
- `scripts/sources/tokyo-metropolitan-art-museum.mjs` 的 v2、v3、v4
- `tokyo-big-sight` 的 v1–v3、`ikebukuro-keizai-shop-changes` 的 v1–v3、
  `activity-filter` / `event-contract` / `run-ingestion` 的 v1–v2

三个后果：

1. **看不出哪份是活的。** 真正生效的链路是
   `update-events-v6 → index-v5 → run-ingestion.mjs(v1) → activity-filter-v2`——
   最新的入口用的却是**旧版**的管线骨架，而更好的 `run-ingestion-v2`（支持多页、
   可注入 fetch 因而可测）被 v5 用完就搁置了。这种错配肉眼几乎发现不了。
2. **测试信号失效。** `node --test` 有 6 个失败，全部来自已被取代的死版本
   （比如 `editorial-context.test.mjs` 期望日文「自然観察」而实现已改成中文「自然观察」）。
   红色成了常态，于是没人再看测试结果。
3. **CI 跑的不是现在这条链路。** `update-events.yml` 跑 v1，新增的 `update-events-v3.yml`
   跑 v3，**没有任何 workflow 跑 v6**。每天自动更新的是两条早已废弃的链路。

## 决定

**不允许用文件名表达版本。** 不出现 `foo-v2.mjs` 这类命名。要改写就改原文件，
历史交给 git。

同时确定的配套约定：

- 每个 `.mjs` 旁边放同名 `.test.mjs`，`npm test` 必须全绿才提交。
- CI 在抓取之前先跑 `npm test`。
- 入口脚本只做接线（`update-events.mjs` 现在只有三行），逻辑放模块里，
  这样"换实现"是改 import，不是复制文件。

## 执行

先把 codex 产出的全部中间版本原样提交一次作为基线（`0731d69`），保证删掉的每一份
都能从历史里找回；再删 27 份死副本、把 18 个生效文件改回无版本号的名字。

保留的实现按"最新且可测"选，因此：

- `run-ingestion` 取 **v2**（原先生效的是 v1）——v2 是 v1 的严格超集：
  多页抓取、`fetchImpl` 可注入。这是本次唯一的行为变更。
- `tokyo-big-sight` 取 v3，`tokyo-metropolitan-art-museum` 取 v4，
  `ikebukuro-keizai-shop-changes` 取 v3，`activity-filter`/`event-contract` 取 v2，
  `editorial-context` 的测试取 v2（v1 那份的日文期望已过时）。

结果：40 个测试全绿，lint 干净，`npm run update-events` 与 `npm run build` 均通过。

## 代价

死副本里可能有还没被采纳的想法（比如 `event-utils.mjs` 里已无调用方的
`mergeAndSelectEvents`）。它们不会消失，但从此只存在于 git 历史里，
要靠 `git log` 而不是 `ls` 才能发现。这是刻意的取舍。
