# 0003 · 候选进池子，发布是一次判决

**日期：** 2026-08-28
**状态：** 生效
**取代：** [0002](0002-闸门要自动化.md) 中「这一轮不做闸门」的部分；0002 的理由（人工审批队列会淹没审批者）仍然成立

## 背景

接完开放数据、来源家族与运营方之后，池子从 34 条涨到 126 条，而且还在涨。
前台一次渲染全部，页面被压垮；同时 0002 定下的「不做人工闸门」意味着任何抓到的
东西都会直接上线。两个问题其实是同一个：**发现与发布没有分开。**

原来的存储也撑不住这件事。`data/events.json` 既是抓取产物又是发布内容，
所以「这条被人看过没有」「它是什么类型」「谁放行的」这类问题没有地方记，
而且每次重抓都会把上一轮的一切覆盖掉。

## 决定

**建一个候选池，用 SQLite，并且把候选和判决分成两张表。**

```
candidates — 抓取找到了什么。每轮重写。
decisions  — 人或规则得出了什么结论。抓取永远不碰这张表。
```

没有 `decisions` 行的候选就是 **pending**。这就是「新东西先在后台等着」的实现方式，
而且它不是一个字段——**没有任何一行抓取代码能把它重置**。

配套的三件事：

1. **`data/pool.db` 是记录，`data/events.json` 是导出。**
   `npm run export-site` 只导出 `state='published'` 的条目。抓取不能让东西上前台，
   导出也不能——只有 `decisions` 表里的一行可以。
2. **按方案 §4.1 的对象模型分类**（`lib/object-type.mjs`）：
   event / exhibition / place / opening / closing / activity / open_facility。
   类型是从来源已有的证据推出来的（changeType、genre 标签、来场对象、日期跨度），不是手填的。
   这不只是为了后台好看：§7.1 要求探索队列一轮里类型多样，而「全都叫活动」是没法保证多样性的。
3. **规则和人走同一扇门。** 判决行里的 `decidedBy` 记的是 `human` 还是 `rule:<名字>`。
   把某一类交给自动闸门，改的是署名，不是表结构。

## 为什么是 SQLite

用的是 Node 内置的 `node:sqlite`，零依赖。选它是因为后台要问的问题 JSON 答不了：
什么在等、属于哪一类、来自哪个源、什么时候第一次见到、谁判的。
`firstSeenAt` 尤其重要——它是「今天真的新来了什么」和「今天只是又抓了一遍」的区别。

代价：`data/pool.db` 是二进制，进 git 之后 diff 不可读。接受这个代价，
因为让它成为派生物就等于把记录放回 JSON，那样这条决定就没有意义了。
人要读的时候有 `data/backstage.json`，那是导出的、可读的、进 git 的快照。

`node:sqlite` 在 Node 22 需要实验开关，24 起稳定，所以 CI 与 `engines` 一起升到 24。

## 前后台两个入口

- **`/backstage`（站上，只读）**——同一套设计语言，分类展示整个池子。
  只读是刻意的：一个公开 URL 不是改状态的地方。
- **`npm run review`（本地，可写）**——放行 / 排除 / 撤销，同样的设计语言。
  写进 git 里的库，一次判断结束就是一次普通提交，不需要后端与鉴权。

**判决不等于发布**：`npm run review` 之后还要 `npm run export-site` 站点才变。
这两件事刻意分开——判断和上线是两个动作。

## 第一条规则

同时加了一条、且只有一条自动规则：`rule:trade_only_admission`，
把 Big Sight 声明 `来場対象者 = 商談`（不含一般）的展会自动排除。
一次判掉 101 条，待定从 227 降到 126。

**加规则的门槛不是「过滤器通常是对的」**，而是证据必须**事实且权威**——
这里是主办方自己填的入场对象，方案 §5.2 第 1 条「普通人可以合法报名或购买入场」
直接不成立。品味判断留给人，直到 `lib/gate-evidence.mjs` 显示某个理由码
在足够样本上确实和人的判断一致。

注意这条比原来抓取期的启发式**更窄**：`商談・一般` 的展会仍然待定等人看，
因为 §5.2 明确说商谈展也可能值得去。

## 顺带取消的东西

`lib/editorial-labels.mjs` 那套单独的「标注」没有了。发布本身成为判决之后，
再维护一套「人觉得这条怎么样」的词汇就是重复的：放行就是想去，排除就是不想去。
分析逻辑搬到 `lib/gate-evidence.mjs`，输入改成池子里的行。

## 代价

- **前台从 126 条掉到 30 条**（扩源前既有的那批被追认为已发布，其余进后台）。
  这是这条决定的直接后果，不是 bug。
- **126 条待定需要人过一遍**，而 0002 说过人工队列会淹没审批者。
  缓解的办法只有一个：从这批判决里长出更多规则。判据面板就是为此存在的。
